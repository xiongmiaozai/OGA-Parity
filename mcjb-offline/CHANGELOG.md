# 更新日志（Changelog）

本文件记录 MC 材质转换器（离线版）的版本变更，遵循 [VERSION.md](VERSION.md) 的三套
版本号策略。所有版本均 100% 本地运行，无联网权限。

---

## [1.4.6] — 2026-11-14（versionCode 11）

### 资源库：分类 / 排列 / 包图标
- 新增「分类与排列」工具条，三种**分组维度**：按时间（今天/昨天/日期）、按类型（Java / 基岩版）、按批次（一次转换的输入+产物归组，Java 在前、基岩版在后）。
- 新增**排序方向**（最新在前 / 最早在前）与**类型过滤**（全部 / 仅 Java / 仅基岩版）。
- 资源库条目显示**包图标**：优先读取包内 `pack_icon.png`（基岩）/ `pack.png`（Java），缺失时回退到彩色字母占位徽标（J=Java 绿 / B=基岩蓝）；图标带内存缓存。
- 数据层 `LibraryStore.Item` 增加 `batchId`：同一次转换的导入包与导出产物共享批次号（旧记录显示「旧记录」兼容）；`iconOf()` 从 zip 根目录安全读取图标字节。
- 「查看」弹窗补充批次号；删除记录时清理对应图标缓存。

## [1.4.3] — 2026-11-14（versionCode 8）

### Bug 根因：转换后的文件「无法下载」
- **根因**：原 `exportPack()` 走 `MediaStore.Downloads` 自动写公共下载目录。Android 11+
  对非媒体文件（`.mcpack`/`.zip` 属 `application/octet-stream`）写入 `MediaStore.Downloads`
  **需要 `WRITE_EXTERNAL_STORAGE` / `MANAGE_EXTERNAL_STORAGE`**，而本应用为「完全离线、
  最小权限」未申请，故 `insert()` 在现代设备上必然失败；且旧代码用
  `catch(Exception){return null;}` 把错误静默吞掉，用户看到「完成」却找不到文件。
- **修复**：下载统一改为 **SAF（`ACTION_CREATE_DOCUMENT`）**——用户主动选位置、系统级
  授权，**无需任何存储权限、离线、全 Android 版本可靠**。

### 新增：独立「资源库」面板（替换原"查看历史"对话框）
- 新 `LibraryActivity`：顶栏返回 + 两组列表——
  - **导入的 Java 资源包**（转换时自动存档，记录原始文件名）
  - **导出的基岩版 .mcpack**（转换成功自动存档）
- 每条支持：**查看**（详情：类型/大小/时间/来源/状态/路径）、**下载**（SAF 导出到本机
  任意位置，含下载目录）、**删除**。
- 转换完成时由 `LibraryStore` 把输入包与产物**落库存档**到应用私有目录并写
  `library.json` 索引，长期保留、不会因缓存被回收而丢失。
- 主界面结果卡原「查看转换历史」改为「打开资源库（导入 / 导出存档）」；
  「用 Minecraft 基岩版打开」通过 `FileProvider` 授权私有 `.mcpack`，可被基岩版导入。
- 移除原先误导性的「保存到下载目录（MediaStore）」按钮。

## [1.4.2] — 2026-11-14（versionCode 7）

### UI 布局修复（全程代码拼装，统一全宽避免散乱）
- 新增 `addBody()` 辅助：主体竖向布局的子控件统一以「全宽 + 上间距」加入，修复此前
  多个控件（状态行、预设水平滚动容器、性能模式开关、高级选项区）因未带
  `LayoutParams` 而 `wrap_content` 左对齐窄条、视觉零散的问题。
- 预设选择器由嵌套 `ScrollView` 改为 `HorizontalScrollView`，水平滑动更顺手。

### 产物下载/保存（转换后拿不到文件）
- 结果卡新增两个可靠保存入口，二者均**离线、无需任何权限**：
  - **保存到下载目录**：走 `MediaStore.Downloads` 自动落盘并反馈结果。
  - **另存为…（选择保存位置）**：通过系统 SAF（`ACTION_CREATE_DOCUMENT`）让用户
    自选位置保存 `.mcpack`，作为某些系统无法自动写入下载目录时的兜底。
- 转换完成后自动尝试写入下载目录；不论成功与否都展示上述按钮，并在状态区给出明确
  提示，不再出现「转换好了却找不到文件」的情况。

## [1.4.1] — 2026-11-14（versionCode 6）

### Bug 修复（选本地文件闪退）
- **根因**：v1.4.0 精简 UI 时删除了「运行日志」视图（`logText`/`logScroll`），对应字段
  不再被 `findViewById` 赋值，恒为 `null`；但 `startConvert()` 中残留一处裸调用
  `logText.setText("")`。只有在「选完文件 → 读取 → 启动转换」这一路径才会执行到该行，
  触发空指针（NPE）导致应用崩溃（闪退）。
- **与权限无关**：选文件走的是系统 `ACTION_GET_CONTENT` + `ContentResolver`，不需要
  存储权限（且应用也未声明 `READ_EXTERNAL_STORAGE`）。
- **修复**：删除该处裸调用，运行日志相关逻辑统一走已带 null 保护的 `appendLog()`。

## [1.2.0] — 2026-11-14（versionCode 3）

### 性能
- **转换内核提速**：PNG 编码关闭 `optimize=True`（第二遍最优霍夫曼搜索在 ARM 上极慢），
  默认压缩级 6；实测对编码环节提速约 10~15%（ARM 上更明显），产物体积仅略增。
- **新增"极速档"（性能模式升级）**：在原有 `max_size=256` 基础上，叠加
  `fast_encode`（编码压缩级降至 4 + 重采样由 LANCZOS 降级为 BILINEAR）。
  强制重采样场景下整组转换再快约 16%，且产物更小（测试 249.7KB → 238.7KB）。
- **多线程并行保留并增强**：S5 阶段仍用线程池（numpy 主动释放 GIL，真并行吃多核）。
  实测 200 组 512px 包：单线程 18.1s → 4 线程 5.2s（3.5×）→ 8 线程 4.3×。
  UI 新增**线程档位（自动 / 4 / 8）**，避免旧机 8 线程抢占反变慢。
- **并行感知 ETA（墙钟速率）**：剩余时间按"已完成组数 / S5 墙钟耗时"估算，天然兼容
  多核，不再因核心数多而高估。

### UI（重做，仍纯原生、离线）
- 新增**预设选择**（标准 / 高度图 / 精细 / 快速 / 自定义），从 Python 侧 `presets()` 拉取。
- 新增**选项区**：兼容模式、性能模式、线程档位、贴图上限档位（512/1024/2048）。
- 新增**进度可取消**：转换中显示"取消转换"按钮。
- 新增**结果页**：12/12 校验通过提示、产物名与大小、**原图/色彩/法线/MER 预览缩略图**
  （此前 Python 已算好但从未展示）、导入与历史入口。
- 新增**转换历史面板**：读取本地 SQLite 历史（最近 50 条）。

### 版本管理
- 引入 git 仓库、`.gitignore`、`VERSION.md`、`CHANGELOG.md`。
- `versionCode` 1→3，`versionName` 1.1.0→**1.2.0**（注：1.1.0 为已发布未入库版本）。
